# 餐廳物語

經營一間台灣小吃店。從一間小小的店面開始，擺放爐具與餐桌、聘請廚師與服務生，
研發菜色、控制食材成本與食安風險，決定走商業午餐、社區早餐還是親子餐廳路線。

> 本分支（`claude/restaurant-game`）是由《復健科診所物語》移植而來的餐廳版；診所版保留在 `claude/rehab-clinic-game`。
> 對照與進度見 `docs/RESTAURANT_DESIGN.md`、`docs/RESTAURANT_PROGRESS.md`。架構文件見 `docs/GAME_ARCHITECTURE.md`、`docs/ARCHITECTURE.md`。

畫面是 2.5D 等角視角的像素風格（致敬 Kairosoft 系列經營遊戲），全部以網頁技術製作，
不需要安裝任何東西。

## 遊玩方式

本遊戲是純靜態網站，需要透過靜態伺服器開啟：

```bash
python3 -m http.server 8000
```

然後用瀏覽器開啟 <http://localhost:8000/>。

本分支尚未加入 `.github/workflows/pages.yml` 的自動部署清單（避免覆蓋診所版網站）；要上線請手動執行 workflow，或把本分支加進 `on.push.branches`。

## 操作方式

| 操作 | 功能 |
|---|---|
| 左鍵點擊 | 建造（依目前選取的工具放置設施、拖曳鋪地板、拆除，或選取客人／員工／設施查看資料） |
| `Shift` + 左鍵 | 連續放置同一種設施（沒按 Shift 的話，放好一個就會取消工具） |
| 右鍵拖曳（或中鍵拖曳） | 平移視角；在建造中單擊右鍵＝取消工具 |
| 滾輪 | 縮放（0.5～2.5 倍） |
| `R`（或 `Alt` + 滾輪） | 旋轉待放置（或搬移中）的設施 |
| `M` | 移動工具：點設備拿起（搬移費＝造價 10%，最少 NT$ 500；原地轉向免費），點空位放下；`Esc`／右鍵取消。手機：長按設備 → 「移動」，拖曳 ✔ 確認 |
| `Esc` | 取消目前工具、關閉面板 |
| `G` | 顯示／隱藏格線 |
| `Space` | 暫停／繼續 |
| `1` / `2` / `3` | 速度 ×1 / ×2 / ×3 |
| `B` `O` `C` `V` `P` `Y` | 開啟 建造／運作／餐廳／一覽／地圖／系統 面板 |
| `?` 或 `F1` | 操作說明 |

右下角也有速度按鈕與「跳過本週」。觸控裝置可以用雙指平移。

## 系統設定：效能診斷、畫質、幀率上限

手機卡頓或發熱時，到「系統 → 設定」：

| 項目 | 說明 |
|---|---|
| **效能診斷** | 打開後畫面左上角會顯示 fps（平均與 1% 最低）、每幀耗時（p50／p95）、模擬／繪製／介面各花幾 ms、場上角色數、畫布實際像素、DPR、畫質等級、美術風格、店面等級與 JS 記憶體。也可以用網址 `?perf=1` 開啟，電腦按 `F3` 切換。 |
| **畫質** | 自動（手機依幀率自動降級，電腦維持最高）／高／中（解析度上限 2 倍、關閉車輛與天氣粒子、行走不搖擺）／低（解析度上限約 1.25 倍、無地面陰影）。立即生效並記在這台裝置。 |
| **幀率上限** | 60（預設）或 30。30 會隔一次才繪製，省電、少發熱；遊戲時間仍依真實秒數前進，速度不變。 |
| **關於 → 版本** | 顯示這份遊戲的建置版本（部署時產生的 `version.json`；本機開發顯示 `dev`）。網頁開著時若有新版本上線，會跳出「有新版本，重新整理即可更新」。 |


## 封面

每次開啟遊戲會先看到封面：「▶ 開始遊戲」（有自動存檔時為「▶ 繼續遊戲」，也可按 Enter／空白鍵），下方是「📲 安裝與全螢幕」（安裝成 App、全螢幕、iPhone 加入主畫面說明）。封面期間遊戲時間靜止。系統 → 設定裡仍保留同一組按鈕（手機／平板）。網址加 `?nocover` 可略過封面；自動化瀏覽器（Playwright 等）預設略過，加 `?cover=1` 可強制顯示。

## 支持作者（捐款頁）

遊戲不處理任何金流，只連到外部贊助頁。把贊助頁網址填進 `js/data/support.js` 的 `SUPPORT.url`（必須是 https）後，封面會出現「☕ 支持作者」按鈕，系統面板會多一個「☕ 支持」分頁；網址留空時兩處都不顯示。頁面文案（免費、自願、付款在外部完成）也在同一個檔案。

## 遊戲循環

### 時間

- 一週等於一個營業日，小吃店每天 08:00 至 20:00 營業（速度 ×1 時約 45 秒真實時間）。
- 客人依時段進場：早上是長輩吃早餐，中午與傍晚是上班族，下午放學後是學生，晚餐時段是親子家庭。
- 每月底結算：發薪水、付房租、設備維護費，並出月結報表（營業額、特色料理、食材成本、毛利率）。

### 資金

- 起始資金 NT$ 120 萬，開店時已先擺好點餐櫃檯、長椅、主廚爐台、冷盤檯、煮麵台、滷肉鍋、例湯鍋、煎台、油炸鍋、飲料吧與三張餐桌，
  並請了主廚、廚師、收銀、外場服務生各一名（扣掉裝潢後約 NT$ 104 萬）。
- 拆除設施退回 50% 建造費；員工人數有店面等級的上限。資金歸零以下太久會倒閉。

### 菜單、特色料理與食材成本（真實價位）

價格與食材成本率集中在 `js/data/fees.js`（2026 年台灣小吃店、簡餐店、熱炒店的常見價位帶）。

- **基本菜單**：招牌主餐 200、麵 130、滷肉飯 70、煎餃 90、鹽酥雞 110、鐵板 240、小菜 50、湯 40、飲料 60、冰品 75（每位）。
  上菜當下就收現金，食材成本（約 22–40%）同時記入支出。
- **特色料理（加點）**：熟成牛排 720、海鮮 480、火鍋 560、炭火燒烤 400、手作甜點 170、精釀啤酒 300。
  需要先研發並蓋好專用設備；在「運作 → 特色定價」可把價格調到 0.5～2.0 倍，定價越高客人越不願意加點、滿意度越低。
- 每位客人都會在最後坐到餐桌內用（`dine`），餐桌與外場服務生決定翻桌速度。
- **每位模擬客人代表多位真實客人**：巷弄小吃店 28 位、社區餐館 40、地區人氣餐廳 50、全台旗艦餐廳 76；
  營業額與食材成本都乘上這個權重，薪水、房租、造價與事件金額則是實際金額。
- **食安風險**：設備太舊、油炸油沒換、衛生事件會累積食安風險；年底衛生局稽查時風險高就會被罰款扣聲譽。

### 專區組合

把特定設施相鄰擺放，會啟動「專區」並提供加成。相鄰指兩個設施的範圍彼此接觸（含斜角）；
一整群相連的設施只要包含專區所需的全部種類即可。同一專區蓋多個不會重複加成，不同專區的加成會疊加（全域上限另計）。共 15 個專區：

- **黃金爐火區**：煮麵台、滷肉鍋與油炸鍋相鄰成一區，基本餐點翻桌率 +20%，長輩滿意度 +8。
- **高端餐飲區**：主廚餐檯、甜點吧與咖啡機相鄰，加點轉換率 +15%，特色料理單價 +10%。
- **親子放電樂園**：兒童遊戲區、軟墊與繪本架相鄰，研發點數獲得 ×1.25。
- **候位舒適區**：長椅、冰水機、綠植與電視牆相鄰，客人耐心 +10%，長輩滿意度 +2。
- **員工喘息站**：休息室旁設冰水機，員工體力消耗降低 10%。
- **學生社群據點**：油炸鍋、飲料吧與冰品檯連成一區，學生客來客 +10%、熟客化 +6%、加點轉換率 +2%。
- **長者友善動線**：至少 3 格坡道緊鄰指示招牌與長椅，長輩滿意度 +6、滑倒風險 −15%、步行速度 +2%。
- **主廚出餐線**：主廚爐台、鐵板檯與煮麵台相鄰，熟客化效率 +4%、研發點數 +6%。
- **冷熱湯飲區**：例湯鍋、飲料吧與冷盤檯相鄰，客人耐心 +3%、基本餐點翻桌率 +3%、上班族滿意度 +3。
- **家庭宴席區**：火鍋桌、四人桌與兒童遊戲區連成一區，家庭客來客 +10%、熟客化 +8%、研發點數 +8%。
- **親子遊戲角**：四人桌、繪本架與軟墊相鄰，家庭客滿意度 +6、所有客人滿意度 +1。
- **宵夜熱炒廊**：熱炒爐、吧台與炭火爐並排成一條廊，加點轉換率 +3.5%、特色料理單價 +3%。
- **員工友善後勤**：休息室、咖啡機、冰水機與綠植連成後勤角，員工體力消耗 −12%、聲譽每週 +0.05。
- **候位咖啡角**：長椅、咖啡機、電視牆與綠植相鄰，客人耐心 +5%、加點轉換率 +1.5%、上班族滿意度 +4。
- **點餐便民區**：點餐櫃檯旁備好招牌、長椅與冰水機，客人耐心 +4%、步行速度 +1%。

可在「一覽 → 專區辭典」查看所有專區：已啟動 n / 共 15、依狀態或類別篩選，每張卡標示已有 ✔／還缺 ✘／需研發 🔒，
並可按「在地圖上看」讓鏡頭飛到該專區。

### 研發點數

每上完一道菜，會產生三種研發點數：**廚藝、設備、服務**。在「運作 → 研發」花費對應的點數，一次研發一項，需要數週完成：

- **廚藝**：鐵板燒技術、招牌食譜、熟成牛排、熱炒鍋氣、手作甜點、長者軟爛餐、火鍋湯底、兒童餐、學生套餐、老字號傳承。
- **設備**：煮麵台效率、保養手冊、冰品設備、炭火燒烤、吧台與啤酒、兒童友善設施、冷鏈管理、排油煙與防滑。
- **服務**：叫號數位化、外場流程、點餐話術、社區口碑、行動點餐 POS、人力排班、套餐會員、展店規劃（第 3、4 級店面都要先完成）、老闆品牌經營。

研發樹做完後，「持續精進」有 6 條可重複升級的項目，提升立即生效、費用隨等級遞增。

### 客人與員工

- 四種客群：**晨間長輩客**、**上班族午餐客**、**放學學生族**、**親子家庭客**，各有不同時段、耐心與加點意願。
  經營方針可選**商業午餐店**、**社區早餐店**、**親子餐廳**，調整各客群比例。
- 客人來店多次會變成**熟客**，熟客帶來聲譽與穩定客源。
- 員工五個職類：**主廚**（主餐、鐵板、主廚特餐）、**廚師**（麵、炸物、熱炒、燒烤）、**吧台師**（飲料、冰品、甜點、吧台）、
  **外場服務生**（帶位、上菜、小菜湯品）、**櫃檯收銀**（點餐結帳，也能顧滷肉鍋、湯鍋與飲料機）。
  各有**技術**、**親和力**與**體力**，太累會變慢，需要休息室或閒置時恢復。
- **設施要有對的人才能運作**：卡片與選取資訊會標出「需要：✔／⚠ 職類」；沒人能操作的設備地圖上會出現 ⚠，客人也不會去排隊。

### 在地事件

- **天氣**：晴天、陰天、午後陣雨、梅雨季、寒流、炎夏高溫、颱風，影響來客與滑倒風險（鋪防滑地墊或坡道可減少）。
- **社區活動**（運作）：宮廟免費供餐、社區試吃、親子廚藝營、公司午餐推廣、里民健走早餐會、長照據點合作午餐、夜市快閃攤位，花錢換一段時間的客源與聲譽。
- **店內看板**：今日特餐、飲料甜度說明、兒童餐推薦、長者養生餐等，調整客群與加點意願。
- **兩難抉擇**：客人要老闆多送一點、只想喝湯不點主餐、一次想訂很多、等太久或嫌太貴的客訴……每個選擇都影響聲譽與營收。
- **隨機事件**：里長邀約、衛生局抽查、地方電視台採訪、客人影片爆紅、員工被挖角、設備召回、颱風淹水、市府補助等。

### 評鑑與擴建

- 每年年底衛生局稽查：無障礙坡道、候位座位、防滑地面、食安風險、客人滿意度。通過得聲譽（高分另有獎勵金），不通過罰款扣聲譽。
- 店面分四級：巷弄小吃店（12×10）→ 社區餐館（14×12）→ 地區人氣餐廳（16×14）→ 全台旗艦餐廳（20×16）。
  升級需要聲譽、年資、員工數、滿意度、坡道、座位與擴建費用，在「餐廳 → 擴建」查看條件。

## 開發注意事項

- 本專案不使用任何建置工具，也沒有 npm 執行期相依套件，不使用外部字型或 CDN 資源。
- 所有使用者可見的文字皆為繁體中文（台灣用語）。
- 修改程式碼後，可用 `node --check <檔案>` 先檢查語法。
- 系統稽核：`node tools/audit.mjs`（Node 無頭執行，約數分鐘；加 `--quick` 較快）會檢查 PRD 功能、五年長跑的數值完整性、存檔／讀檔一致性與邊界情況。
  瀏覽器回歸測試：先 `python3 -m http.server 8201`，再 `node tools/play.mjs`、`node tools/smoke.mjs`。
- 專區辭典：`node tools/audit.mjs --only zones`（15 個專區逐一強制啟動／拆掉一件即失效、坡道 2／3 格邊界、疊加與上限、存讀檔、擺得進 12×10 起始地）；UI 版先 `python3 -m http.server 8217`，再 `node tools/zonesui.mjs [--shots <dir>]`（辭典、篩選、在地圖上看、四種視窗尺寸、兩種美術風格）。手工驗證過的擺法在 `tools/zonelayouts.mjs`。
- 效能診斷測試：先 `python3 -m http.server 8213`，再 `node tools/perftest.mjs`（加 `--quick` 略過兩次 12 秒的實測）。
- 部署時 `.github/workflows/pages.yml` 會寫入 `_site/version.json`（`{"sha","built"}`）。本機沒有這個檔案，版本顯示 `dev`，也不會檢查更新（網址加 `?ver=1` 可強制查詢，測試用）。
- 部署到 GitHub Pages 時只需要 `index.html`、`css/`、`js/`（見 `.github/workflows/pages.yml`）；若新增執行期需要的頂層資料夾，記得同步更新該檔的 `cp` 清單。
- 模組之間的名稱與介面以 `docs/ARCHITECTURE.md` 為準，不要自行更改契約。
- 遊戲狀態需可序列化為 JSON，不可存放函式、class 實例、Map 或 Set。
- 若要調整畫面風格，請優先使用 `css/style.css` 內定義的顏色變數（`:root`）與共用類別，
  例如 `.btn`、`.panel-title`、`.card`、`.tab`、`.bar`，避免重複寫樣式。
