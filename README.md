# 復健科診所物語

經營一間台灣的復健科診所。從一間小小的診間開始，決定要做健保、還是走自費路線，
安排物理治療、職能與語言治療的動線，在健保與自費之間找到自己的平衡點。

畫面是 2.5D 等角視角的像素風格（致敬 Kairosoft 系列經營遊戲），全部以網頁技術製作，
不需要安裝任何東西。

## 遊玩方式

### 在本機執行

本遊戲是純靜態網站，需要透過靜態伺服器開啟（直接雙擊 `index.html` 因瀏覽器對
ES module 的限制無法載入）。在專案資料夾執行：

```bash
python3 -m http.server 8000
```

然後用瀏覽器開啟 <http://localhost:8000/>。

### 線上遊玩（GitHub Pages）

所有資源都使用相對路徑，可以直接部署到 GitHub Pages：

1. 到 GitHub 專案頁面的 **Settings → Pages**。
2. Source 選擇你要發布的分支與根目錄（`/`）。
3. 儲存後，等待幾分鐘即可透過 Pages 網址遊玩。

## 操作方式

| 操作 | 功能 |
|---|---|
| 左鍵點擊 | 建造（依目前選取的工具放置設施或鋪設地板） |
| 右鍵拖曳 | 平移視角 |
| 滾輪 | 縮放 |
| `R` | 旋轉待放置的設施 |
| `Esc` | 取消目前工具、關閉面板 |
| `G` | 顯示／隱藏格線 |
| `Space` | 暫停／繼續 |
| `1` / `2` / `3` | 速度 ×1 / ×2 / ×3 |

左側按鈕可開啟「建造、運作、診所、一覽、地圖、系統」等面板。右下角也有速度按鈕。

## 遊戲循環

### 時間

- 一週等於一個營業日，診所每天 08:00 至 20:00 營業。
- 4 週為一個月，12 個月為一年。
- 每月底結算：發薪水、付租金與維護費，並結算健保收入。

### 健保與自費

- **健保**：治療會累積健保點數，月底才依點值換算成收入。
  點數過多時點值會下降（所謂「點數稀釋」），因此一直堆便宜的電熱療，收入很快就會停滯。
- **自費**：治療當下即時收取現金，可以自行調整定價，但會影響病患的接受度。
- 研發自費項目與提升自費轉換率，是擺脫點數稀釋的主要方法。

### 專區組合

把特定設施相鄰擺放，會啟動「專區」並提供加成。相鄰指兩個設施的範圍彼此接觸（含斜角）。

- **黃金三寶區**：熱敷、電療、牽引相鄰擺放，提高健保翻桌率，並提升長輩的滿意度。
- **高階自費專區**：徒手治療室、體外震波、咖啡區相鄰擺放，提高自費轉換率與自費定價空間。
- **早療放電樂園**：球池、軟墊、書架相鄰擺放，提高研究點數的獲得量。

可在「一覽 → 專區組合辭典」查看所有專區的需求與目前是否啟動。

### 研究點數

每完成一次療程，會產生三種研究點數：**醫術、儀器、服務**。
在「運作 → 研發」花費對應的點數，解鎖新的設施、療程與經營效果。
員工訓練也會消耗服務點數。

### 病患與員工

- 病患會依季節、天氣與社區活動進場，依序經過掛號、候診、治療與結帳。
- 病患的滿意度會影響診所聲譽，聲譽又會影響之後的病患數量。
- 員工（醫師、物理治療師、職能治療師、語言治療師、櫃檯護理師）各有技能與體力，需要適度安排與訓練。

### 其他

- 月底可能會遇到健保署抽審、衛教看板、社區衛教等事件，也會有需要抉擇的情境。
- 診所有擴建門檻，達成條件後才能擴大經營規模。
- 遊戲提供三個存檔欄位與自動存檔，並可匯出、匯入 JSON。

## 專案結構

```
index.html               入口頁
css/style.css            基礎樣式（像素風、按鈕、面板、顏色變數）
css/ui.css               介面補充樣式
js/main.js               啟動與主迴圈
js/core/                 常數、事件匯流排、狀態、格點
js/data/                 遊戲資料（設施、療程、研發、事件、文字）
js/sim/                  模擬邏輯（病患、員工、經濟、研發、事件、存檔）
js/render/               等角 Canvas 繪製與輸入處理
js/ui/                   頂欄、側欄、面板、提示、對話框
tools/                   開發與測試工具
docs/ARCHITECTURE.md     架構、模組介面與視覺規格（開發者請先閱讀）
```

## 開發注意事項

- 本專案不使用任何建置工具，也沒有 npm 執行期相依套件，不使用外部字型或 CDN 資源。
- 所有使用者可見的文字皆為繁體中文（台灣用語）。
- 修改程式碼後，可用 `node --check <檔案>` 先檢查語法。
- 模組之間的名稱與介面以 `docs/ARCHITECTURE.md` 為準，不要自行更改契約。
- 遊戲狀態需可序列化為 JSON，不可存放函式、class 實例、Map 或 Set。
- 若要調整畫面風格，請優先使用 `css/style.css` 內定義的顏色變數（`:root`）與共用類別，
  例如 `.btn`、`.panel-title`、`.card`、`.tab`、`.bar`，避免重複寫樣式。
